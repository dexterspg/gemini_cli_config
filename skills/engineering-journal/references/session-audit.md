# Session audit: what in a session belongs in the config

Run only when the user says "audit this session". Output is proposals; apply no config change without a yes, run no eval suite. Two writes need no yes and are reported: a parked line added to the to-do (step 2) and a stale line removed from it (step 7).

**Store:** `C:/workarea/gemini-config-todo.md`, two sections: "Session audit, seen once" (patterns) and "Session audit, proposals". File missing or unwritable: say so and stop; never write the entries elsewhere. One dated line per entry: `- [ ] YYYY-MM-DD, session <id>: <pattern>. Evidence: <turn or file>. Home if it repeats: <home>.` The session id is the transcript's file name under `~/.gemini/antigravity-cli/brain/<conversation-id>/`; a finished or compacted session is read from that file.

1. **List candidates.** Each pattern, rule or fact the session used that a later session could reuse, with where it happened (a turn or file). None found: report "no candidates" and still run step 7.
2. **Check recurrence** against the seen-once lines. A repeat counts only from a different session: it becomes a proposal and its seen-once line is removed. A first sighting is parked with a new line (verdict `PARK`). A verified fact (a team's statement, a source-read, a count a `CONFIRMED` script gave) needs no repeat: go to step 3.
3. **Ask the Decision guide's first question** (`~/.gemini/skills/quality-guardian/EVIDENCE-agent-design.md` → "Decision guide"): would the model do it without the text? Yes → verdict `DROP`.
4. **Pick one home**, first match: a script or hook (fixed steps); a project skill or its `CLAUDE.md` when the pattern is that project's (grep `{project-root}/.gemini/skills/**` and `{project-root}/GEMINI.md` first; the project wins, per global `CLAUDE.md` → "Project Skill vs Global Skill Precedence"); a global skill line (team knowledge the model lacks); a reference file (loads rarely); memory (a personal preference only).
5. **Cost:** tokens added, and what it replaces. Flag a file that grows more than 5% over its size before the edit (`quality-guardian/CHECKLIST-agents-skills.md` → "For Skill Files"). End the report with `Behaviour gate: unproven (no suite).`
6. **Report** a table: candidate, evidence, recurrence (first / repeat), home, cost, verdict (`PROPOSE`, `PARK` or `DROP`). Show before and after for each `PROPOSE`; the main session decides. Add each `PROPOSE` to the proposals section. Example row: `Count before extracting | turn 12, size=1 search | first | hurl-conventions | +30 tokens | PARK`.
7. **Stale entries are removed,** run after step 2 so a repeat is counted first. Check each seen-once line and each proposal; delete one when any is true, whatever its age: already applied elsewhere; the file, step or fact it names no longer exists or changed; a later change made it unnecessary. Deadlines are the latest an entry may stay: a seen-once line 60 days after its date, a proposal 14 days after its date (rerun the audit if still wanted). A declined proposal is deleted at once. Report what was removed and why. Deadlines run only when an audit runs; the user can say "audit this session" to clear them.
